# Design

## Context

See proposal.md for the motivation. The shell is the package `splitty-gui` in `crates/splitty-tauri`: `src/lib.rs` (composition root, in-process embedded service on macOS and Linux), `src/client_ipc.rs` and `src/client_ipc/` (document proofs, the IPC carrier, `bootstrap.js` and its `bootstrap.test.cjs`), `src/remote.rs` (remote windows), `src/windows_wsl.rs` (WSL provisioning and the owner helper on Windows), `src/navigation.rs`, `src/capability.rs`, `src/editor.rs`, `src/downloads.rs`, `src/login_path.rs`, `src/main.rs`, `build.rs` (the app manifest of 23 commands), `permissions/autogenerated/` (23 files), `tauri.conf.json`, `tauri.macos.conf.json`, `tauri.windows.conf.json`, `icons/` (six files), `resources/README.md` and the ignored `resources/splitty-wsl-x86_64.tar.gz*` and `gen/`.

The native app does not link the crate. It builds on `crates/splitty-client-core`, which links `splitty-server`, `splitty-remote` and `splitty-transport` directly. Several build, packaging and runtime paths of the native app still point into the Tauri crate's directory or reuse its identifiers; they are listed under "What the native app still takes from the shell".

## Goals / Non-Goals

**Goals:**

- Delete the crate and every build input, CI job, script, Make target, packaging file and doc section that exists only for it.
- Delete server and remote code whose only caller was the shell or a form of `desktop-backend` only the shell family needed, with the evidence below.
- Keep every path the native app, its packages and the release use, moving files out of `crates/splitty-tauri/` where the native app still needs them.
- Bring the specs, the architecture model and the planning text in line in the same change.

**Non-Goals:**

- `frontend/` and everything of the browser access path (proposal, Out of scope).
- New native features to replace what only the shell had: remote-only Windows, per-host windows, the login-shell `PATH`, "show in folder" for saved files.

## Decisions

### D1. What goes with the crate

The whole directory `crates/splitty-tauri/`, its entry in `Cargo.toml` `[workspace] members`, and its packages in `Cargo.lock` (`splitty-gui`, `tauri`, `tauri-build`, `tauri-plugin-opener`, `tauri-plugin-single-instance`, `wry`, `tao`, `webkit2gtk`, `gtk` and what only they pull in), regenerated with `cargo update --workspace` and checked with `cargo metadata --locked`. `tauri-winrt-notification` stays in the lockfile: GPUI's `notify-rust` uses it on Windows.

Only the shell used these outside the crate: `scripts/testing/tauri-webkit-smoke.py` and `tauri-webkit-smoke/` (10 files), `tauri-windows-native-smoke.py` and `tauri-windows-native-smoke/` (27 files), `tauri-windows-guard.test.py`, `tauri-wkwebview-smoke.py`, `tauri-wkwebview-smoke-test.py`, `tauri-wkwebview-smoke.md`; `packaging/macos/build.sh` (the Tauri DMG; the native one is `packaging/macos/native/build.sh`); `packaging/linux/splitty.desktop` (`Exec=splitty-gui`) and `packaging/linux/splitty.png`, used only by `make install-tauri` and `scripts/generate-icons.sh` (the native packages use `packaging/linux/native/splitty.desktop`); `packaging/linux/nostrip/strip`, a `strip` stand-in that no script, workflow or Make target references any more; the `.gitignore` entries `crates/splitty-tauri/gen/` and `crates/splitty-tauri/resources/splitty-wsl-x86_64.tar.gz*`.

### D2. Server and remote code that only the shell family used

Each candidate was checked against `crates/splitty-client-core` and `crates/splitty-gpui`:

| Candidate | Evidence | Outcome |
|---|---|---|
| `desktop-backend --backend ssh` with `--target`, `--remember-target`, `--update` (`crates/splitty-server/src/main.rs`, `Commands::DesktopBackend`) and `native::helper::ssh` with its `failure_frame` and the two unit tests `ssh_failure_preserves_*` (`src/native/helper.rs`) | The native app starts `desktop-backend` only in `WslLaunch::arguments` (`crates/splitty-client-core/src/owned_service.rs`), always as `--backend embedded --owner`; it opens hosts through its service's hub (`EmbeddedService::host_stream`, `splitty-server` `hub`). The Tauri crate itself never started the SSH form; it used `splitty-remote` in-process (`src/remote.rs`, `src/client_ipc.rs`). The only callers are the smoke test `owned_ssh_helper_detaches_its_real_exec_pipes_and_leaves_both_daemons_untouched` (`tests/daemon_lifecycle.rs`) and argument cases in `native_child_arguments_and_legacy_bootstrap_input_fail_before_backend_creation` and `editor_cli_tests::native_helpers_and_all_owner_entry_points_are_unavailable_to_grants` (`src/main.rs`). | Removed (RTS-4). The value parser accepts only `embedded`; the three SSH options are deleted, so they are unknown arguments (usage error, status 2). |
| `tunnel::open_with_update` and `Failure::from_error_budgeted` (`crates/splitty-remote/src/tunnel/mod.rs`) | Outside the Tauri crate, only `native::helper::ssh` calls them; `tunnel::open` delegates to `open_with_update(…, false, …)`. The hub has its own update intent (`splitty-server/src/hub/connector.rs`). | `from_error_budgeted` goes; `open_with_update` is folded into `open`. `SshRemote::with_update` and its `update` intent go only if no caller is left after that (a worker checks with `git grep`); the supervisor's own update handling (`tunnel/supervisor.rs`) stays. |
| `desktop-backend --backend embedded` without `--owner` (`native::helper::embedded`) | No released app starts it; the Tauri shell on Windows used `--owner`, on Unix an in-process service. Smoke tests prove the owned-child lifetime with it (`owned_native_child_pipes_end_only_their_embedded_sessions`, run on Linux and macOS CI). | Kept (RTS-4); candidate for the protocol follow-up. |
| `serve --desktop-stdio` and `serve --remote` (hidden refusing flags) | Part of `splitty serve`, which `remove-browser-access` removes whole. | Kept here (RTS-5). |
| `hosts::record_recent_if_visible`, `MigrationOffer`, `owner::Owner`, `owner::Connection`, `bridge::NativeBridge`, `native::client::Connector`, `control::spawn_at`, `catalog::Role::Main`/`Role::Remote` | Used by the hub (`hub/native.rs`, `hub/failure.rs`), the gateway, the host relay and client-core (`owned_service.rs`, `embedded.rs`, `api_stream.rs`, `connection.rs`). `Role::Setup` exists only inside the Tauri crate. | Stay. |
| `testdata/remote-editor.json`, `editor-folders.json`, `editor-files.json` | Read by client-core (`native_workspace/editor_uri.rs`) and the frontend tests besides the Tauri crate. | Stay. |
| `crates/splitty-tauri/src/login_path.rs` | No counterpart in the native app (`git grep` finds no `PATH` adoption in `splitty-gpui`, `splitty-client-core`). | Removed with the crate; the spec requirement goes with it and the gap becomes a finding (RTS-3). |

Comments that name the shell or its remote windows are reworded where they describe current code: `crates/splitty-server/src/control.rs` (the Tauri app's embedded server), `crates/splitty-client-core/src/native_workspace/editor_uri.rs` (shared vectors), `crates/splitty-core/src/native_api.rs` (`LocalHub` "unavailable to remote windows": host relays), `crates/splitty-server/src/host/bridge.rs` and `crates/splitty-transport/src/negotiation.rs` ("remote window"), `crates/splitty-gpui/src/startup/wsl.rs` ("the distribution the web app remembered"). The fixture name `splitty-gui` in `crates/splitty-core/src/pty/cli_path.rs` (`discovers_only_an_executable_installation_local_cli`) becomes `splitty-gpui`; the test's logic does not change.

### D3. What the native app still takes from the shell

- **Icons.** `packaging/linux/native/build.sh` installs `crates/splitty-tauri/icons/icon.png`, `packaging/windows/native/bundle.ps1` uses `icons/icon.ico`, and `crates/splitty-gpui/build.rs` embeds `../splitty-tauri/icons/icon.ico` as the Windows executable's resource. These two files move to `crates/splitty-gpui/icons/` (`git mv`, bytes unchanged); `32x32.png`, `128x128.png`, `128x128@2x.png` and `icon.icns` go. macOS keeps `icon-macos.icns` at the repository root. `scripts/generate-icons.sh` writes the two files to the new place and no longer writes the Tauri sizes or `packaging/linux/splitty.png` (RTS-6).
- **The local Windows payload.** `packaging/windows/build.ps1` writes the WSL backend archive to `crates/splitty-tauri/resources/` and passes it to `native/bundle.ps1` from there. It moves to `build/windows-payload/` (already ignored through `build/`) (RTS-8). CI is not affected: `windows-tauri.yml`'s native job downloads the artifact into `payloads/`.
- **The Windows installer workflow.** `windows-tauri.yml` builds the native installer in its `native` job and is called by `release.yml`. It is renamed to `windows-installer.yml` (workflow name "Windows installer"), loses the `web` input and job, and `release.yml` calls the new file. `server-payloads.yml` stops uploading the `frontend-dist` artifact, which only the `web` job downloaded; its frontend build stays because the static server still embeds `frontend/dist` (RTS-7).
- **Identifiers kept for upgrades.** The native Windows app remembers its distribution in `%APPDATA%\com.splitty.app\windows.json` (`crates/splitty-gpui/src/startup/wsl.rs`, `state_path`), the Tauri app's identifier directory, and reads the Tauri app's `pendingDistro`/`selectedDistro` there. `packaging/windows/native/installer.nsi` removes the earlier web app's `splitty-gui.exe` (`LEGACY_BINARY`) when it installs over it. Both stay so installations of earlier releases keep upgrading in place and keep their chosen distribution; only comments change (RTS-8).
- **NSIS lookup.** `packaging/windows/native/bundle.ps1` also looks for `makensis.exe` in the Tauri CLI's cache (`%LOCALAPPDATA%\tauri\NSIS`). That cache is no longer filled by any build of this repository; the lookup goes, and `packaging/windows/README.md` names NSIS 3 as a prerequisite (RTS-8).
- **The frontend build in CI.** The macOS job builds the frontend for the shell and for `cargo build -p splitty-server`, which embeds `frontend/dist`. The step stays (renamed "Build frontend") until `remove-browser-access` (RTS-12).
- **Intel Macs.** `release.yml` builds and publishes `Splitty_<version>_x64.dmg` on `macos-15-intel`, so Intel Macs keep a desktop app; the sentence "no native package for Intel Macs" in `docs/native-ui-handoff.md` is stale and is corrected.

### D4. CI after the removal

`ci.yml`: the job `tauri-linux` goes. The job `tauri-macos` becomes `macos` ("Native app (macOS)", cache key `macos`) and loses "Check portable WKWebView harness preparation", "Lint and test native macOS application" (`-p splitty-gui`), "Run packaged WKWebView lifecycle smoke", "Verify WKWebView remote isolation and slow consumers" and the upload of `tauri-macos-native-evidence`; it keeps the runtime prerequisites, the frontend build, the native build, test compilation, the disk image, the core tests and the native carrier, endpoint and exposure checks. The `rust` job runs `cargo clippy --locked --workspace --all-targets -- -D warnings` and `cargo test --locked --workspace`; its comment about the shell's own jobs goes. `release.yml` calls `windows-installer.yml` and loses its comment that CI keeps the Tauri app building. `codeql.yml` and `.github/dependabot.yml` name nothing of the shell and stay; `deny.toml` keeps `unmaintained = "workspace"` with a comment that no longer names Tauri (RTS-11).

### D5. Make targets

`dev-tauri`, `$(BUILD)/splitty-gui`, `check-splitty-not-running`, `$(BUILD)/Splitty.app`, `dmg`, `install-tauri` and `uninstall-tauri` go, with their `.PHONY` entries and the "Legacy web app" section. `dev`, `test`, `native-package`, `install-no-gui`, `uninstall-no-gui`, `uninstall-config`, `icons` and `clean` stay. `docs/development.md` names the files an earlier `make install-tauri` left (`/Applications/Splitty.app` with `com.splitty.app` on macOS; `~/.local/bin/splitty-gui`, `~/.local/share/applications/splitty.desktop` and `~/.local/share/icons/hicolor/128x128/apps/splitty.png` on Linux) so they can be removed by hand (RTS-10).

### D6. Specs

The deltas follow the rule "only the shell → REMOVED with a reason; shared with the native app → MODIFIED, keeping what the native app guarantees". The native behavior each MODIFIED requirement keeps was checked in code:

- Editor handoffs: `crates/splitty-client-core/src/native_workspace/editor_uri.rs` (`remote_editor_uri`, `local_editor_uri`, the shared vectors), dispatched with `cx.open_url` from `crates/splitty-gpui/src/workspace/terminal_menu.rs`; the generic opener refuses `vscode:`, `zed:`, `sftp:` (`crates/splitty-client-core/src/external_links.rs`); CLI editor requests need the user's Open (`native_workspace/editors.rs`).
- macOS/Linux hosting: `EmbeddedService::start` builds the service in-process with no daemon discovery, restoration or listener (`crates/splitty-client-core/src/embedded.rs`).
- Windows hosting: `WslLaunch::arguments` (`--backend embedded --owner`), the owner close with a bounded grace before killing only the bridge (`crates/splitty-remote/src/owner.rs`, `bridge.rs` `finish_owner`), the "WSL is not installed" and "No WSL 2 distribution was found" failures (`crates/splitty-gpui/src/startup/wsl.rs`), one backend per app instance (`docs/native-ui-handoff.md`, draft `native-windows-one-backend`).
- Payloads: `release.yml` builds the Linux and macOS native apps with all four `SPLITTY_REMOTE_PAYLOAD_*` variables.

OpenSpec refuses a MODIFIED block that drops a scenario of the current requirement. Where a scenario only described the shell, the delta keeps its name and states what holds now (`Dedicated native command scope`, `Show the saved file`, `Remote only`, `Repeated start for the same distribution`); the browser scenario `Remote window has a host query` stays unchanged for `remove-browser-access`. `Desktop Stdio Lifetime Binding` had a scenario that cannot be restated (an SSH helper detaching from a host daemon), so it is REMOVED and its embedded guarantees are ADDED as `Desktop Backend Child Lifetime`.

No capability loses all requirements: `desktop-remote` keeps Remote Folder Editor Handoff, SSH Path Of A Remote Folder, Local Folder Editor Handoff, Confirmed CLI Editor Handoff and Local Editor Preferences, and keeps its name (RTS-9). OpenSpec carries a delta's Purpose only for new capabilities, so the Purpose lines of `desktop-remote` ("remote windows in the desktop apps") and `server-modes` ("how desktop launchers bind the server's lifetime") are edited in the main specs after the archive, in the same commit as the synced specs.

### D7. Architecture impact

- Removed: the container `splitty.desktop` ("Legacy desktop app", `architecture/landscape.c4`) with all its components in `architecture/desktop.c4` (`app_main`, `app`, `client_ipc`, `editor`, `downloads`, `login_path`, `navigation`, `capability`, `remote`, `windows_wsl`) and every relationship from them into `splitty.remote.*`, `splitty.transport.*`, `splitty.server.*` and `splitty.core.*`; the relationships `splitty.desktop -> splitty.web` and `splitty.desktop -> wsl`; the views `desktop` and `app_root` (`architecture/views.c4`); `splitty.desktop.client_ipc` from the `connections` view and `splitty.desktop.remote` from the `remote` view. The file `architecture/desktop.c4` is deleted.
- Changed: descriptions of the system `splitty`, the containers `core` and `web` (no "desktop shell's WebView", no "legacy desktop app") in `landscape.c4`; the `containers` view description; `architecture/README.md` (the `desktop.c4` row, the crate and root lists naming `splitty-gui`, `splitty_tauri_lib`, `app`, `app_main`). `server.c4`'s `native` component ("owned desktop child pipes") stays true for `--owner`.
- `cargo test` (`architecture/check`) must pass with the crate and the model removed together.
- `docs/architecture.md` concept sections: Server Modes (the Tauri hosting paragraph, Login shell `PATH`, the shell's document authority, Remote windows, recent hosts of the Tauri app, the `client_ipc`, provider, carrier and memory-contract paragraphs, the SSH form of `desktop-backend`), Listener and authority inventory (rows "Tauri local UI" and "Separate remote window", the packaged asset schemes and `make dev-tauri`), Module Map (the `splitty-gui` sentence), Session Output (the Tauri carrier sentence), File Transfers (the Tauri download hook and `reveal_download`), Remote Screens (the desktop app's remote window entry), the terminal link and editor handoff paragraphs (Tauri, `open_remote_editor`, `open_local_editor`), Close assessment (quitting the desktop shell).

### D8. Coordination with `remove-browser-access`

That change is written in parallel and lands after this one. Both edit `docs/architecture.md`, `docs/development.md`, `docs/networking.md`, `SECURITY.md`, `CLAUDE.md`, `openspec/config.yaml`, `.github/workflows/ci.yml`, `server-payloads.yml`, `roadmap/README.md`, `openspec/open-decisions.md` and several drafts, and both may touch requirements in `access-control`, `client-connections`, `desktop-remote`, `server-modes` and `terminal-sessions`. Its deltas for requirements this change modifies or adds (Explicit Remote Editor Dispatch, Remote/Local Folder Editor Handoff, Desktop Backend Child Lifetime with its `serve --desktop-stdio` scenario, Desktop App Hosting On macOS And Linux with its `serve --daemon` sentence, Bounded Delivery, Resource Admission, Feature Parity Without Hidden Listeners, Saving An Offered File) are written against the main specs as this change's archive leaves them.

### D9. Overlaps with open changes

No open change has a MODIFIED or REMOVED delta for a requirement this change removes or modifies (checked over every `openspec/changes/*/specs/`: `native-drawer-host-ports`, `native-feature-gaps`, `native-host-update`, `native-notification-badges`, `native-notification-controls`, `native-remote-screen-create`, `native-remote-screen-rename`, `native-remote-screens`, `native-remote-ux`, `native-screen-reorder`, `native-terminal-context-menu`). Two touch the same capability with other requirements: `native-remote-ux` ADDs Native Offered Files to `terminal-sessions` next to the modified Saving An Offered File, and `native-feature-gaps` changes `display-zoom`, which this change leaves alone. Ten of them still carry an unchecked full-gate task naming `--exclude splitty-gui`; those lines are brought to the new gate.

## Risks / Trade-offs

- [Windows machines without WSL lose the only desktop path, also from source] → recorded as RTS-1; `native-windows-without-wsl` carries the note; the release notes of the next version say so.
- [The native app on macOS started from the Dock has launchd's `PATH`, so an SSH `ProxyCommand` from Homebrew fails] → this is already the case for every released app; the finding and RTS-3 keep it visible, and `login_path.rs` with its tests stays in the history for the follow-up.
- [Removing the SSH helper also removes its smoke coverage of SSH detach] → the hub's SSH detach and daemon survival keep their own smoke tests (`remote_connect.rs`, `the_hub_updates_a_host_daemon_of_another_version`, `connect_reconnects_and_hands_over_sessions_through_real_ssh`).
- [`cargo test --workspace` now builds `splitty-gpui` on every Linux machine that runs the full check] → it already did with `--exclude splitty-gui` (only the Tauri crate was excluded); the libghostty-vt and xkbcommon prerequisites in `docs/gpui-spike.md` are unchanged.
- [A renamed workflow breaks links to `windows-tauri.yml` runs] → old runs stay under their name in the Actions history; `docs/development.md` names the new file.
- [Leftover installs of the Tauri app] → macOS `Splitty.app` with `com.splitty.app` is replaced by the native bundle of the same name (NDD-4); Windows "Splitty Web" installs separately and stays until uninstalled; Linux source installs are listed in `docs/development.md` (D5).

## Migration Plan

One commit for the removal (code, lockfile, CI, packaging, model, docs), then the archive commit with the synced specs and the two Purpose edits. Rollback is a revert of the removal commit; the archive commit is reverted with it. No data migration: the native app keeps reading `%APPDATA%\com.splitty.app\windows.json`.

## Provisional decisions

Dated 2026-11-15, each marked (provisional, tbd), open to the maintainer's feedback; each also gets a bullet in `openspec/open-decisions.md`.

- **RTS-1** (provisional, tbd): the shell is removed now, before the draft `native-windows-without-wsl` is implemented. Until then Windows machines without WSL (remote-only use over `ssh.exe`) have no desktop app, also not from source. Intel Macs are not affected: releases publish the native `x64` disk image. Alternative: implement `native-windows-without-wsl` first.
- **RTS-2** (provisional, tbd): no replacement for the separate per-host remote window; the native app shows a host's screens in its own window. Alternative: a native window per host.
- **RTS-3** (provisional, tbd): `server-modes`, Desktop App Command Search Path is removed with the shell, and the native app's missing login-shell `PATH` becomes a finding in `docs/issues/openspec-baseline-findings.md`; moving `login_path.rs` into the native app is a change of its own. Alternative: move it into `splitty-gpui` within this change and keep the requirement.
- **RTS-4** (provisional, tbd): the SSH form of `desktop-backend` (`--backend ssh`, `--target`, `--remember-target`, `--update`) and `native::helper::ssh` are removed; `--backend embedded` with and without `--owner` stays. Alternative: also remove the form without `--owner`, which no released app starts.
- **RTS-5** (provisional, tbd): the hidden refusing flags `serve --desktop-stdio` and `serve --remote` stay until `remove-browser-access` removes `serve`. Alternative: remove them here.
- **RTS-6** (provisional, tbd): `icon.png` and `icon.ico` move to `crates/splitty-gpui/icons/`; the other Tauri icon sizes, `icon.icns` and `packaging/linux/splitty.png` go; `icon-macos.icns` stays at the root. Alternative: a shared `packaging/icons/` directory.
- **RTS-7** (provisional, tbd): `windows-tauri.yml` is renamed `windows-installer.yml` without the `web` input and job, and `server-payloads.yml` drops the `frontend-dist` artifact. Alternative: keep the file name.
- **RTS-8** (provisional, tbd): the local Windows build writes the WSL payload to `build/windows-payload/`; the native app keeps `%APPDATA%\com.splitty.app\windows.json` and the installer keeps replacing `splitty-gui.exe` of earlier releases; `bundle.ps1` no longer looks for NSIS in the Tauri CLI's cache. Alternative: a new state directory with a one-time migration.
- **RTS-9** (provisional, tbd): the capability `desktop-remote` keeps its name for the editor-handoff and SSH-path requirements; only its Purpose is rewritten. Alternative: move them to a new capability such as `editor-handoff`.
- **RTS-10** (provisional, tbd): the Tauri Make targets go without aliases, `uninstall-tauri` included; `docs/development.md` names the files an earlier `make install-tauri` left. Alternative: keep `uninstall-tauri` for a release or two.
- **RTS-11** (provisional, tbd): entries of `openspec/open-decisions.md` that concern only the shell are removed, as RES-3 did for Electron; the historical findings in `docs/security/findings.md` keep their entries with a dated note; `deny.toml` keeps `unmaintained = "workspace"` with a comment that no longer names Tauri. Alternative: keep the decisions marked as moot, or check unmaintained crates for all dependencies.
- **RTS-12** (provisional, tbd): CI keeps building the frontend in the macOS job and in `server-payloads.yml` because the server still embeds it; `remove-browser-access` removes those steps. Alternative: an empty `frontend/dist` as `release.yml`'s version-skew job uses.
