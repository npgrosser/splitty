# Open decisions for the maintainer's review

Changes do not wait for the maintainer. A decision an agent takes on its own, to keep going, is marked "(provisional, tbd)" in the change (a design's "Provisional decisions" section, or a light proposal's "Decisions") and gets a bullet here, so the maintainer can review them in one place instead of digging through archived changes.

When the maintainer decides a point, a follow-up change carries it if it changes behavior, and the point leaves this file. A point stays as it is until then; silence is not confirmation, but the provisional choice keeps working in the meantime.

Each point names what holds now, the alternative, and where it is recorded.

## Points

- **`arrange-panes` D1 whole grid** (2026-10-30, provisional, tbd): after a drag or a divider move the window sends its whole grid as `arrange_panes`, and the server replaces the root layout with it (new node IDs, last writer wins between windows). Alternative: one `move_pane` or `resize_split` per gesture, which needs the server's node IDs in the window and a translation for each of dockview's move paths.
- **`arrange-panes` D2 pane set** (2026-10-30, provisional, tbd): an arrangement must hold exactly the root layout's panes; pane IDs the screen does not hold are left out instead of rejected, so a window with panes the server never knew does not resync after every drag. Alternative: reject unknown IDs too.
- **`arrange-panes` D3 when it is sent** (2026-10-30, provisional, tbd): 100 ms after a panel move or the end of a divider drag, only when it differs from the last snapshot's or sent arrangement (sizes within 0.005); never on a tab click (that sends `select_tab` since `remember-selected-tab`), a window resize or during a snapshot rebuild. Alternative: on every layout change, which risks two windows answering each other's nudges.
- **`arrange-panes` D5 floating and popout groups** (2026-10-30, provisional, tbd): outside the arrangement; a drag between the grid and a floating group is rejected and the pane returns, and nothing is sent while a popout group exists. Alternative: floating entries with bounds and server-kept floating IDs in the arrangement.
- **`remember-selected-tab` D1 an op of its own** (2026-10-31, provisional, tbd): a tab click sends `select_tab` with the pane ID, and the server makes it its slot's active pane in the root layout or a floating entry; a rejection is only logged, without `mux.op_failed`. Alternative: the grid as `arrange_panes`, which gives fresh node IDs, nudges every other window into a rebuild and cannot reach floating groups.
- **`remember-selected-tab` D2 no nudge** (2026-10-31, provisional, tbd): other windows are not nudged after `select_tab`; they keep their own tabs and see the choice on their next fresh build. Alternative: a nudge, which rebuilds every other window's layout for a click without changing what it shows.
- **`remember-selected-tab` D3 when it is sent** (2026-10-31, provisional, tbd): 100 ms after an active panel change or a removed panel, for every grid or floating group with two or more tabs whose shown tab is not the one the server has as far as the window knows; none during a snapshot, none for a popout group; a snapshot alone sends nothing. Alternative: only the group the user touched, which leaves tabs a window kept through a reconnect unreported.
- **`remember-selected-tab` D4 first pane as fallback** (2026-10-31, provisional, tbd): a fresh build shows a slot's first pane when it names no active pane or an unknown one, as the server does after removing the active pane. Alternative: the last one, which dockview shows by adding the tabs in order.
- **`remember-selected-tab` D5 focused group** (2026-10-31, provisional, tbd): which group has keyboard focus stays the window's; the server keeps none. Alternative: a screen-level focused pane in the model.

- **`zoom` steps** (2026-10-27, provisional, tbd): the zoom shortcuts move through Chromium's levels, 50 to 300 %. Alternative: 10 % steps.
- **`zoom` stored per server** (2026-10-27, provisional, tbd): every level change writes `appearance.zoom` to `config.toml` of the server that serves the window (a remote window's host for a remote window). Alternative: keep the level only for the session.

- **`move-pane-to-screen` op and place** (2026-10-27, provisional, tbd): one workspace op `move_pane_to_screen` moves a pane with its running session; in an existing screen it becomes the active tab of the first slot of the grid (depth-first), a new screen goes right after the source; a managed job's pane does not move; "Move to Screen" in the pane and tab menus lists only the same server's screens. - **`move-pane-to-screen` empty source and focus** (2026-10-27, provisional, tbd): a screen left without panes closes with the move; the moving window switches to the target and shows the pane in front. Alternative: keep an empty screen with a fresh shell; stay on the source.
